# Adapter Examples

These examples describe the current wrapper-first adapter scaffolds. They are
intended to show how each runtime reaches the shared Python contract rather
than to imply native bindings or production support.

## Python

- Installation assumptions: the repo is installed in a `uv` environment with
  the maintained Python dependencies available.
- Minimal run: `uv run python -m lifecourse.model_contract --request specs/core-api/fixtures/v1/model-run-request.fixture.json`
- Expected output: a JSON response matching the shared contract response shape.
- Limitations: this is the reference implementation, not an adapter.

## R

- Installation assumptions: `R`, `testthat`, and the package scaffold are
  available in `bindings/r`.
- Minimal run: source `bindings/r/R/lifecourse_contract.R` and call the wrapper
  helper with the shared request fixture.
- Expected output: a validated contract response via the Python reference
  contract.
- Limitations: wrapper-first only; no native binding layer.

## Julia

- Installation assumptions: Julia can activate the `bindings/julia` package
  scaffold and run `Pkg.test`.
- Minimal run: load `LifecourseContract` and call the wrapper helper with the
  shared request fixture.
- Expected output: a validated contract response via the Python reference
  contract.
- Limitations: wrapper-first only; no native binding layer.

## Go

- Installation assumptions: Go can build the `bindings/go` module and `python3`
  is available on PATH.
- Minimal run: `go run ./cmd/lifecourse-contract --request ../../specs/core-api/fixtures/v1/model-run-request.fixture.json`
- Expected output: the Python reference contract writes or prints a JSON
  response payload.
- Limitations: the scaffold shells out to Python and does not embed the model.

## TypeScript

- Installation assumptions: Node and TypeScript can build the `bindings/typescript`
  scaffold and `python3` is available on PATH.
- Minimal run: build the scaffold and invoke the wrapper command on the shared
  request fixture.
- Expected output: a JSON response generated by the Python reference contract.
- Limitations: local typings are intentionally minimal and wrapper-first.

## C#

- Installation assumptions: .NET 11 SDK is available and `python3` is available
  on PATH.
- Minimal run: run the `bindings/csharp` CLI with `--request` pointing at the
  shared request fixture.
- Expected output: the Python reference contract writes or prints a JSON
  response payload.
- Limitations: the scaffold is experimental and process-based.

## Rust

- Installation assumptions: Cargo can build the `bindings/rust` crate and
  `python3` is available on PATH.
- Minimal run: run the `lifecourse-contract` binary with `--request` pointing
  at the shared request fixture.
- Expected output: the Python reference contract writes or prints a JSON
  response payload.
- Limitations: this is a contract consumer scaffold, not a migrated kernel.
